# ถอดเทป (transcription) สำหรับ Live Clip — ผลสำรวจ 27 ต.ค. 2026

ตรวจจากหน้า pricing และเอกสารทางการของแต่ละเจ้าในวันเดียวกัน แล้วมีผู้ตรวจซ้ำอีกชั้น

## ข้อเท็จจริงที่ตัดสินทางเลือก

- **CPU ของ NAS** = Intel Atom C3538 2.1 GHz, 4 คอร์, **ไม่มี AVX/AVX2**, RAM 16 GB แชร์กับ probook
  → รันโมเดล ASR ในเครื่องนี้ไม่คุ้ม (PyTorch/NeMo บน CPU ไม่มี AVX ช้ามาก และแย่ง CPU กับการตัดคลิป)
- **Typhoon ASR** (`typhoon-ai/typhoon-asr-realtime`, 114M, CC-BY-4.0) คือ open model ไทยตัวเดียวที่อ้างว่ารันบน CPU ได้
  CER ราว 10% บนเสียงทีวี; จุดอ่อนทางการคือ คำอังกฤษถูกทับศัพท์เป็นไทย, ไม่มี diarization, timestamps เป็นค่าประมาณ
  ตัวเลขความเร็ว CPU ทางการมีแค่ตัวอย่างเดียว (RTF 0.29 ไม่บอกรุ่น CPU)
- **WhistleCutter** (เครื่องของทีมตัด, Apple Silicon) รัน Typhoon ASR อยู่แล้วพร้อม silence-chunking (`backend/typhoon_worker.py`)
  → คลิปจาก Live Clip เปิดใน WhistleCutter ก็ได้บทถอดเสียงไทยทันทีโดยไม่ต้องเขียนอะไรเพิ่ม
- **Typhoon hosted API** ฟรี แต่เป็น beta research showcase, ไม่มี timestamps ในเอกสาร และ T&C ข้อ 4 ให้สิทธิ์ถาวรเอา input ไปเทรน → ห้ามส่งเสียงข่าว
- **Gemini free tier** เงื่อนไขระบุว่าคน Google อ่านได้และเอาไปพัฒนาโมเดล → ห้ามส่งเสียงข่าว ต้องเป็น paid tier
- **OpenAI whisper-1** (ตัวเดียวของ OpenAI ที่ให้ timestamps) จะปิด 26 ก.พ. 2027 → ไม่สร้างบนมัน

## แบบที่เสนอ

1. **ขั้นแรก (ไม่ต้องเขียนโค้ด)** คลิปที่ตัดจาก Live Clip → เปิดใน WhistleCutter → Typhoon ถอดในเครื่องทีมตัด
2. **ขั้นสอง ถอดสดบนเซิร์ฟเวอร์** worker ตัวหนึ่งหั่นบัฟเฟอร์เป็นก้อน 20 วินาที (10 segment ที่มีอยู่แล้ว เวลาเริ่ม = PROGRAM-DATE-TIME ของ segment แรก)
   ส่ง Gemini 3.5 Transcribe (paid) → เก็บ (เวลาเริ่ม, เวลาจบ, ข้อความ) ลง SQLite → หน้าเว็บมีช่องค้นคำ กดแล้วกระโดดไปเวลานั้นและตั้ง In/Out ได้
   ไทม์ไลน์เดียวกับ player และตัวตัด จึงกระโดดแล้วตรงเฟรม
3. **ถอดคลิปที่ตัดแล้วบนเซิร์ฟเวอร์** ใช้ API เดียวกัน เพิ่มไม่ถึง $1/วัน

สิ่งที่ยังไม่มีใครวัด: คุณภาพไทยของ Gemini 3.5 Transcribe บนเสียงข่าวจริง ต้องลองกับคลิปของทีมก่อนจ่ายรายเดือน
